## 2024-05-24 - Accessibility for Mock Interfaces
**Learning:** Even when building a purely aesthetic, non-functional "mock" interface (like a fake WhatsApp chat used for a demo or visual flourish), the semantic HTML elements (like `<button>`) still require accessibility attributes such as `aria-label`. Screen readers parse the DOM identically regardless of whether a button triggers actual business logic or just an animation. Missing labels on icon-only buttons in these visual components create a confusing, unlabeled experience for assistive tech users traversing the page content.
**Action:** When using `<button>`, `<input>`, or interactive elements strictly for visual mockups or animation triggers without explicit text content, always add descriptive `aria-label` or `aria-hidden="true"` depending on whether the mock interface is meant to be explorable by assistive tech or skipped entirely.
